# hxwl-12 督导排班与危机随访交接台

在原心理咨询个案记录基础上扩展：个案风险、随访截止、咨询师/督导/会谈室排班，
以及危机改派的交接单与排期版本留痕。

## 技术栈

React 19 + Vite + TypeScript + 纯 CSS，localStorage 持久化（无后端）。

## 本地运行

```bash
npm install
npm run dev      # http://localhost:5112
npm test         # 判定层事务规则冒烟测试（24 条）
npm run typecheck
npm run build
```

## 分层（按 数据 / 判定 / 存储 拆分）

- `src/domain/` **数据层**：`types.ts` 领域模型（个案、随访、排班、交接单、版本），
  `clock.ts` 时间工具，`seed.ts` 演示数据与"违规示例批次"。
- `src/rules/` **判定层**：纯函数，不触碰存储。
  - `schedule.ts`：人员时段重叠、会谈室冲突、高风险 24h 督导接单、完成会谈门槛。
  - `transitions.ts`：登记 / 接单 / 批量提交 / 冻结 / 更正 / 交接 / 随访等状态流转。
  - `helpers.ts`：违规结果、id、版本号工具。
  - `selftest.ts`：规则冒烟测试。
- `src/storage/` **存储层**：`repo.ts` 单一快照原子读写 localStorage；
  `useAppState.ts` 仅在判定通过时落库。
- `src/ui/` **界面层**：个案登记台、督导排班台、改派交接台、版本台。

## 核心业务规则

1. **个案登记**：风险等级、随访截止、咨询师；高风险登记即启动 24 小时督导接单窗口并建立首次随访。
2. **排班整笔提交**，出现以下任一情况**整笔拒绝并保留原计划**（草稿不入计划）：
   - 同一咨询师 / 督导时段重叠（含同批草稿互相重叠）；
   - 同一会谈室时段冲突；
   - 高风险个案 24 小时内无督导接单。
3. **高风险未接单不得完成会谈**（按钮禁用并有规则兜底）。
4. **改派先建交接单**：督导确认前原咨询师不释放、未来排期不转移；
   未完成随访随交接单承接（`carriedFollowUpIds` 留痕）。
   督导确认时校验新咨询师是否时段冲突，冲突则拒绝确认、保留原计划；也可驳回。
5. **排期冻结**：冻结后更正必须填写原因，生成自增修订号的版本记录。
6. 个案、排班、交接、版本同居于一个状态快照，**刷新后四者一致**。

## 演示路径

- 排班台点「载入违规示例批次」→「整笔提交」，可见红色横幅列出三类冲突且原计划不变。
- 个案台 C-203 为高风险未接单：完成会谈被阻止；选择督导接单后解锁。
- 交接台对种子中待确认的 C-203 交接单执行确认/驳回，观察原咨询师锁定与随访承接。
- 排班台冻结后对已冻结会谈做「更正」，留原因并在版本台生成新版本。
